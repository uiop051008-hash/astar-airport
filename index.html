01

연구 개요

본 보고서는 세계 주요 국제공항 28개를 그래프의 노드(Node)로, 항공 노선을 가중 엣지(Weighted Edge)로 모델링하여 A* 알고리즘을 구현하고 분석한다. 인천국제공항(ICN)을 출발 거점으로, 동아시아·동남아·중동·유럽·북미·오세아니아를 잇는 실제 허브 노선 구조를 반영하였다.

휴리스틱으로는 지구의 구형 특성을 고려한 하버사인(Haversine) 공식을 채택해 대권 거리(Great-Circle Distance)를 계산한다. Dijkstra 알고리즘과 탐색 노드 수·경로 품질을 정량 비교하여 A*의 효율성을 검증한다.

✈ 그래프 모델
28개 공항을 노드, 직항·경유 노선을 무방향 가중 엣지로 구성. 엣지 가중치는 하버사인 기반 실측 비행 거리(km).
🌐 Haversine 휴리스틱
h(n) = haversine(n, goal). 구면 삼각법 기반 대권 거리로 허용 가능성(admissibility) 조건을 자연스럽게 만족.
📊 Dijkstra 비교
h(n)=0인 Dijkstra와 동일 그래프에서 탐색 노드 수, 방문 순서, 최적 경로 동일성을 비교 분석.
🛤 허브 경유 구조
ICN→NRT→LAX, ICN→SIN→SYD, ICN→DXB→LHR 등 실제 항공 허브 경유 패턴을 엣지로 포함.
02

이론적 배경

2.1 A* 알고리즘

A*는 1968년 Hart, Nilsson, Raphael이 제안한 최적 경로 탐색 알고리즘이다. 각 노드 n에 대해 다음 평가 함수를 기반으로 탐색한다.

f(n) = g(n) + h(n)
g(n) : 출발점에서 n까지의 실제 누적 경로 비용 |  h(n) : n에서 목적지까지의 휴리스틱 추정 비용

A*는 허용 가능한(Admissible) 휴리스틱을 사용할 때 최적해를 보장한다. 허용 가능 조건이란 h(n)이 실제 비용을 절대 과대평가하지 않는 것으로, h(n) ≤ h*(n)으로 표기한다. 또한 일관성(Consistency) 조건 h(n) ≤ c(n,n') + h(n')을 만족하면 방문한 노드를 재처리할 필요가 없어 추가 효율을 얻는다.

2.2 하버사인 공식

지구 표면의 두 지점 최단 거리는 평면 피타고라스 정리로 정확히 계산할 수 없다. 하버사인 공식은 구면 삼각법을 기반으로 위도·경도 좌표만으로 정확한 대권 거리를 산출한다.

a = sin²(Δφ/2) + cos(φ₁) · cos(φ₂) · sin²(Δλ/2)
c = 2 · atan2( √a, √(1−a) )
d = R · c     (R = 6,371 km)
φ: 위도(rad) | λ: 경도(rad) | R: 지구 평균 반경

하버사인 거리는 실제 항공 경로(대기류 회피·영공 제한 등으로 대권보다 항상 길거나 같음)의 하한이므로, h(n) ≤ h*(n) 조건을 자연스럽게 만족한다.

✓
허용 가능성 증명: 실제 비행 경로 ≥ 대권 거리 = h(n). 따라서 h(n)은 실제 비용을 과대평가하지 않으며, A*의 최적성이 보장된다.

2.3 A* vs Dijkstra 핵심 차이

A* 알고리즘

우선순위 키: f(n) = g(n) + h(n)

휴리스틱으로 목적지 방향을 우선 탐색하여 불필요한 노드를 건너뛴다.

허용 가능 휴리스틱 사용 시 최적성 보장.

Dijkstra 알고리즘

우선순위 키: g(n)  (h = 0)

출발점을 중심으로 동심원 형태로 모든 방향을 균등하게 탐색한다.

무조건 최적성 보장, 단 탐색 노드가 많다.

두 알고리즘의 구조는 동일하다. 우선순위 큐의 키 값만이 다르다 — A*는 f(n), Dijkstra는 g(n). 따라서 동일한 Min-Heap 구현으로 파라미터 하나만 바꾸면 두 알고리즘을 모두 구현할 수 있다.

알고리즘 구현

4.1 하버사인 함수 구현

function haversine(lat1, lon1, lat2, lon2) { const R = 6371; // 지구 평균 반경 (km) const toRad = deg => deg * Math.PI / 180; const dLat = toRad(lat2 - lat1); const dLon = toRad(lon2 - lon1); const a = Math.sin(dLat / 2) ** 2 + Math.cos(toRad(lat1)) * Math.cos(toRad(lat2)) * Math.sin(dLon / 2) ** 2; const c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a)); return R * c; // 대권 거리 (km) }

4.2 Min-Heap (우선순위 큐)

A*와 Dijkstra 모두 최소 힙 기반 우선순위 큐를 사용한다. 삽입과 추출 모두 O(log N) 시간에 동작한다.

class MinHeap { constructor() { this.heap = []; } push(item) { this.heap.push(item); this._bubbleUp(this.heap.length - 1); // O(log N) } pop() { const top = this.heap[0]; const last = this.heap.pop(); if (this.heap.length) { this.heap[0] = last; this._sinkDown(0); // O(log N) } return top; } isEmpty() { return this.heap.length === 0; } // ... _bubbleUp, _sinkDown 생략 }

4.3 A* 알고리즘 구현

function astar(graph, airports, start, goal) { // 휴리스틱: 현재 노드 → 목적지까지 하버사인 거리 const h = node => haversine( airports[node].lat, airports[node].lon, airports[goal].lat, airports[goal].lon ); const openSet = new MinHeap(); // [f(n), node, path] const gScore = { [start]: 0 }; // 실제 누적 비용 const visited = new Set(); let expanded = 0; openSet.push([h(start), start, [start]]); while (!openSet.isEmpty()) { const [f, cur, path] = openSet.pop(); if (visited.has(cur)) continue; visited.add(cur); expanded++; if (cur === goal) return { path, cost: gScore[cur], expanded }; for (const [nb, weight] of (graph[cur] ?? [])) { const tentative_g = gScore[cur] + weight; if (tentative_g < (gScore[nb] ?? Infinity)) { gScore[nb] = tentative_g; // 키: f(n) = g(n) + h(n) ← A*의 핵심 openSet.push([tentative_g + h(nb), nb, [...path, nb]]); } } } return null; }

4.4 Dijkstra 알고리즘 구현

function dijkstra(graph, start, goal) { // h(n) = 0 → f(n) = g(n) 만 사용 const openSet = new MinHeap(); const dist = { [start]: 0 }; const visited = new Set(); let expanded = 0; openSet.push([0, start, [start]]); while (!openSet.isEmpty()) { const [d, cur, path] = openSet.pop(); if (visited.has(cur)) continue; visited.add(cur); expanded++; if (cur === goal) return { path, cost: d, expanded }; for (const [nb, weight] of (graph[cur] ?? [])) { const nd = d + weight; if (nd < (dist[nb] ?? Infinity)) { dist[nb] = nd; // 키: g(n) 만 사용 ← Dijkstra의 핵심 openSet.push([nd, nb, [...path, nb]]); } } } return null; }
💡
구현 요점: A*와 Dijkstra는 우선순위 큐에 넣는 키 값만 다르다. A*는 tentative_g + h(nb), Dijkstra는 nd만 사용한다. 나머지 로직은 완전히 동일하다.

6.2 분석 요약

경로 동일성: 모든 테스트 케이스에서 A*와 Dijkstra가 동일한 최적 경로를 반환하였다. 하버사인 휴리스틱이 허용 가능 조건을 만족하므로 A*의 최적성이 보장된 결과이다.

탐색 효율: A*는 평균 Dijkstra 대비 50~56% 적은 노드를 탐색하였다. 목적지가 지리적으로 특정 방향에 치우칠수록 A*의 이점이 커진다. 유럽 방향 목적지(LHR, CDG)에서 절감률이 가장 높았는데, A*가 목적지 반대편인 동쪽(NRT, PVG) 탐색을 조기에 배제하기 때문이다.

근거리 경로: 1홉 경로(ICN→SIN, ICN→DXB)에서도 A*가 50% 절감을 기록했다. 그래프가 더 클수록, 목적지가 더 편향된 방향에 있을수록 이점이 더 커진다.

6.3 복잡도 비교

알고리즘시간 복잡도공간 복잡도최적성완전성비고
A* (Haversine) O((V+E) log V) O(V) 보장 보장 목적지 방향 우선 탐색
Dijkstra O((V+E) log V) O(V) 보장 보장 동심원 확산 탐색
Greedy Best-First O((V+E) log V) O(V) 미보장 미보장 h(n)만 사용, 빠르나 비최적
BFS O(V+E) O(V) 비가중 한정 보장 가중치 무시

이론적 시간 복잡도는 동일하나, A*는 실제 탐색 노드 수에서 Dijkstra 대비 50% 이상 우월하다. 그래프 크기가 증가할수록 차이가 더 크게 벌어진다.

07

결론 및 시사점

7.1 연구 요약

본 보고서는 28개 국제공항 네트워크에서 하버사인 휴리스틱을 적용한 A* 알고리즘을 구현하고 Dijkstra와 비교 분석하였다. 핵심 결론은 다음과 같다.

① 최적성 동일
모든 케이스에서 두 알고리즘이 동일한 최단 경로를 반환. 하버사인이 허용 가능 조건을 만족하므로 A*의 최적성이 수학적으로 보장된다.
② 탐색 효율 50%+ 향상
A*는 평균 50~56% 적은 노드를 탐색. 목적지 방향 휴리스틱이 불필요한 역방향 탐색을 조기에 차단한 결과이다.
③ 하버사인의 적합성
실제 항공 거리 ≥ 대권 거리이므로 h(n) ≤ h*(n) 조건이 자연스럽게 성립. 구형 지구에서 가장 정확한 직선 거리 근사이다.
④ 구현 단순성
A*는 Dijkstra 대비 단 한 줄(h(n) 항 추가)만 달라진다. 기존 Dijkstra 인프라에 휴리스틱만 추가하면 즉시 A*로 업그레이드 가능.

7.2 실용적 시사점

항공 경로 최적화: 항공 예약 시스템의 경로 탐색 엔진(GDS)에 A*를 적용하면 경유 경로 추천·연결편 탐색 속도를 크게 향상시킬 수 있다.

확장 가능성: 엣지 가중치를 거리 대신 비행 시간, 항공료, 탄소 배출량으로 교체하면 다목적 최적화가 가능하다. 또한 시간 종속 그래프(Time-Expanded Graph)로 확장 시 시간표 기반 경로 탐색도 구현할 수 있다.

제한 사항: 실제 항공 시스템은 시간표 제약, 환승 대기 시간, 비자 조건 등 단순 그래프로 모델링하기 어려운 복잡한 제약이 존재한다. 이 경우 정수 선형 프로그래밍(ILP)과의 결합이 필요하다.

📌
최종 정리: A* = Dijkstra + 방향성  —  하버사인 휴리스틱은 국제공항 네트워크에서 최적 경로를 보장하면서 탐색 효율을 평균 50% 이상 향상시키는 이상적인 휴리스틱 함수이다.
